# 冠英 · 海外销售工作台

面向商用车制动片出口团队。销售可以按市场发现企业、打开业务证据、核实采购角色，也可以在同一工作台处理 Facebook 评论、Messenger、Facebook 表单、微信客服及人工补录的询盘。界面、API 和数据库实际联动，模拟消息明确标记来源。

## 启动

需要 Docker 和 Docker Compose v2 或以上。在本文件所在目录执行：

```sh
docker compose up -d --build --wait
```

工作台在 [localhost:8080](http://localhost:8080)，接口清单在 [localhost:8080/docs](http://localhost:8080/docs)。健康检查为 `GET /api/health`。Compose 默认仅绑定本机，API 容器保持在内部网络。SQLite 保存在命名卷 `sales_data`，普通 `docker compose down` 后数据仍保留。若端口占用，将 `.env.example` 复制为 `.env` 并修改 `PORT`。首次构建下载基础镜像及依赖，在 Node 构建阶段执行 TypeScript 检查和 Vite 打包。运行时由 Nginx 提供本地静态资源。

本地开发使用 Python 3.12 和 Node.js 22.12+。在项目根目录执行

```sh
python -m pip install -r src/api/requirements.txt
npm --prefix src/web ci
npm --prefix src/web run build
python -m uvicorn src.api.main:app --reload --host 127.0.0.1 --port 8000
```

打开 [localhost:8000](http://localhost:8000)。FastAPI 同源提供 `src/web/dist`，SQLite 默认位于 `data/leads.sqlite3`。修改前端时可在第二个终端执行 `npm --prefix src/web run dev`，打开终端显示的地址，Vite 会热更新组件并将 API 请求转发至 8000 端口。直接启动 Python 时使用进程环境变量，Compose 会读取根目录 `.env`。

总览页按工作台数据展示待回、夜班、认领和客户指标。点击指标可进入对应队列，点“查看跟进简报”可按优先级、当前销售或采购能力打开具体记录。简报在本地汇总，每条来信的分析方式显示在收件箱。

## 管理员与团队登录

首次部署后，从项目目录在交互式终端创建第一位管理员。命令会提示输入至少 12 个字符的临时密码。直接运行 Python 服务时，在使用相同 `DB_PATH` 的终端执行第二种命令。

```sh
# Docker Compose
docker compose exec api python -m src.api.accounts init-admin --username admin --name 工作台管理员

# 本地 Python
python -m src.api.accounts init-admin --username admin --name 工作台管理员
```

打开工作台，用刚创建的账号登录并设置个人密码。点击侧栏底部的姓名，进入「成员管理」添加销售或管理员、停用账号或重置临时密码。成员可以在「我的账号」修改自己的密码和退出登录。忘记密码由管理员重置，管理员丢失密码时，部署维护者可运行 `docker compose exec api python -m src.api.accounts recover-admin --username admin`。

普通登录会话最长 8 小时，勾选「保持登录 14 天」后可跨浏览器重启保留会话。修改密码会使本账号其他设备退出，重置密码或停用会使该账号全部会话失效。HTTPS 部署设置 `SESSION_COOKIE_SECURE=1` 后重建 API 容器。项目的本地 HTTP 回环部署使用默认值 0。

## 三分钟走通销售流程

1. **买家发现**　选择“马来西亚／维修厂／已核验样例”，打开证据并将一家企业加入档案。配置搜索密钥后，切换“实时网页搜索”并更换市场或关键词。查询失败和零结果会直接显示。
2. **客户档案**　核对企业官网、社交主页、公开业务联系方式、实际业务类型与采购能力，记录“统一备货还是客户自带”等下一步。来源页、已知业务事实和采购结论分别保留。
3. **渠道模拟器**　填入询价样例并发送；保持事件编号再次发送可验证去重。点击“同会话新消息”后修改原文，会追加到原单。可以改变接收时间来演示最近夜班。
4. **询盘收件箱**　进入新询盘，查看原文、来源、型号和原始数量单位，分配负责人并关联企业。登记线下实际发出的回复后，“未回复”标记消失。客户再次来信后恢复待回。无法自动接入的视频号原生评论可由销售补录。
5. **跨班交接**　“夜间待回”显示最近北京时间 20:00 至次日 08:00 期间还有未回复来信的有效询盘。“我的”“待认领”“已结束”支持不同岗位。跨渠道确认同一采购后，由销售选择目标询盘并合并。原消息、事件 ID 和跟进历史均保留。

## 跟进受阻时寻找替代买家

在「询盘收件箱」选择询盘，关联企业档案后展开「寻找替代买家」。用已有的 L&R Haulage 档案和「本地公开资料」即可试用。未分派的询盘点击「认领并查找」，已有负责人的询盘点击「查找并推荐」。查找会保留原处理状态。

每次最多推荐三家。负责人可在侧栏 Copilot 助手的「替代买家」中查看待办，其他成员仍可在共享询盘查看结果。交接询盘后，待办跟随当前负责人。已有客户显示档案与跟进负责人；新候选可加入客户档案。同一原企业的候选标记「不相关」后，再次查找会排除该候选。

本地模式使用带出处的公开企业资料，包括马来西亚车队、维修和配件经销企业，以及工作台内有核查日期和业务证据的档案。配置 `BRAVE_API_KEY` 后可主动选择实时搜索。推荐卡列出市场与业务重叠、业务原文、查阅日期、公开联系渠道和采购能力。只有负责人填写双方竞争事实和公开原文并确认后，才会显示「竞争关系已人工核实」。配置实时搜索时，编辑依据内也可主动检索同时提及双方的竞争线索。

## 可用数据及运行模式

| 能力 | 无密钥启动 | 接入条件 |
|---|---|---|
| 企业发现 | 三家已公开核验的马来西亚样例，按类型及关键词筛选 | `BRAVE_API_KEY` 开启实际搜索。搜索结果是待核验候选；标题可修正，搜索地区需核实 |
| 消息分析 | 本地中英等语言关键词和型号、数量规则，保留原文，可人工纠正意图 | 可选兼容 Chat Completions 的模型。显式设置 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY` 后，消息正文将发给指定供应方；接口失败回退本地规则 |
| 入站渠道 | 模拟器、人工补录、持久化去重与人工回复登记 | Meta Page 签名回调和微信客服加密回调需要企业授权与外网 HTTPS。配置与覆盖范围见渠道手册 |
| 负责人 | 按当前登录成员筛选“我的”，负责人可从启用成员中分派 | `AUTO_ASSIGN=1` 给新询盘分配当前未结束工单最少的销售 |
| 演示与真实数据 | 首次初始化四条标记“模拟数据”的询盘及一条公开企业档案 | 干净部署前设置 `DEMO_DATA=0`。设置 `ENABLE_SIMULATOR=0` 可关闭模拟入口。已有数据不受参数切换影响 |

此版本覆盖第一条赛题。界面中的编码用于识别采购意图和交接，技术选型和正式核价属于后续业务。工作台和业务 API 使用团队账号及服务端会话。渠道回调沿用平台签名校验。

## 仓库结构

| 路径 | 用途 |
|---|---|
| `src/web/` | Vue 3 单文件组件、TypeScript 接口类型、Vite 构建和 Nginx 配置 |
| `src/api/` | FastAPI、数据模型、SQLite、线索发现、渠道适配、消息归并 |
| `docs/` | 原始需求分析、获客调研和联调手册 |
| `tests/` | API 回归、并发去重、平台回调及真实浏览器烟测 |
| `scripts/` | 可重复执行的目标验收命令 |
| `compose.yaml` | 前后端镜像、健康检查、回环端口和持久化卷 |

## 验收

```sh
python -m pip install -r tests/requirements.txt
python -m playwright install chromium
python -m scripts.goal
```

仓库的 `goal` 验收入口从锁文件安装前端依赖，再执行 TypeScript 检查、Vite 构建、API 测试、Chromium 烟测和 Compose 配置检查。要同时构建并启动容器，可执行 `python -m scripts.goal --docker`。该选项保留启动成功的服务供演示。
