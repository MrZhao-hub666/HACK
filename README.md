# 冠英 · 海外销售工作台

面向商用车制动片出口团队。销售可以按市场发现企业、打开业务证据、核实采购角色，在同一收件箱分派 Facebook、微信客服、WhatsApp、Instagram、X、TikTok、Telegram 和 LINE 的客户来信。模拟消息和人工补录均标记来源。

## 本地整合开发

在 Windows 项目根目录依次运行 `start-backend.bat` 和 `start-frontend.bat`，然后打开销售工作台。需要 Docker Desktop、uv、Python 3.12 和 Node.js 22.12+。首次运行前端前先执行 `npm --prefix src/frontend ci` 安装依赖。后端脚本启动 PostgreSQL 和带热重载的 FastAPI，前端脚本在 `src/frontend` 下执行 `npm run dev`。[销售工作台](http://127.0.0.1:5174)

| 服务 | 本机地址或位置 |
| --- | --- |
| 统一 Vue 工作台，后续 UI 设计入口 | `src/frontend`，端口 5174 |
| 统一 FastAPI，含获客、登录、选型与报价 | `src/backend/api/main.py`，本机端口 8081 |
| 产品目录模块、两级匹配与 Excel 同步 | `src/backend/app`，由同一个 API 进程加载 |
| PostgreSQL 16 | `catalog` 数据库，本机默认端口 25432。销售表在 `sales`，目录在 `public`、`domestic_catalog`、`foreign_catalog` |

本机 PostgreSQL 端口可在根目录 `.env` 中通过 `PG_PORT` 覆盖。Windows 如提示 Docker 无法绑定原端口 `55432`，将 `PG_PORT` 改为 `25432` 后重新运行启动脚本。

首次运行请在另一终端为本地工作台创建管理员，按提示设置自己的密码。

```powershell
.\.venv\Scripts\python.exe -m src.backend.api.accounts init-admin --username admin --name 工作台管理员
```

在「询盘收件箱」选中客户，打开「智能选型」。点击「根据询盘匹配型号」会读取最近最多 30 段客户来信、登记的销售回复和本次补充原话，调用本地目录匹配。客户补充框只参与当前匹配。系统保留有歧义的候选，返回追问、匹配依据、产品图和目录出处。销售确认规格、数量和计价单位后可以保存报价草稿，缺少有效价目时显示「待核价」。同一工作台可按询盘回看最近 25 份草稿。报价快照和询盘关联在同一数据库事务中保存。

在侧栏打开「销售助手」，输入客户需求，例如「客户要配鼓式刹车片，旧件编号 FMSI 4702a」。模型理解自然语言，目录规则读取明确的编号和尺寸、核对规格并选择追问。点击型号卡片可在右侧查看图片、参数和目录出处，窄屏上详情显示在对话下方。点击「复制对客答复」可复制本轮答复。匹配到有效目录价时，答复包含计价单位、单价、数量和总额。预设材料价显示为内部试算，缺少有效目录价时客户答复提示待核价。

目录尺寸齐全时，在销售助手选定型号并补充材质即可看到试算单片价，补充数量后显示总额。按套采购时，可填写「半金属，100 套，每套 4 片」试算套价和总额。公式所需的尺寸有缺项时，补齐尺寸即可试算，也可输入已核单价及对应单位，例如「单价 35 元/套」计算内部合计。单独核算可在「跟进简报 → 报价问答」输入「外弧 200，宽度 100，厚度 18/22，半金属，100 片多少钱？」。尺寸按毫米填写。

在 [quote_config.json](src/backend/api/quote_config.json) 直接填写材料名和对应数字，统一为人民币元/吨。预设包括半金属、低金属、无石棉有机、陶瓷基、无铜陶瓷、玻纤增强、矿物纤维增强及芳纶增强八档。数值用于演示和内部试算，正式对客金额取自有效企业价目。后端每次试算读取配置。

从 GitHub 克隆即可导入三份目录工作簿、PDF 原页和资料包实拍图。首次启动会将目录导入本地 PostgreSQL，可直接演示真实型号、目录出处和实拍三视图。仓库提供网页尺寸的照片副本，本地有企业原资料包时优先读取原图。Docker 部署在仓库根目录的 `.env` 填写 `SALES_LLM_API_KEY`、`SALES_LLM_BASE_URL` 和 `SALES_LLM_MODEL`；本机开发也可继续使用 `src/backend/.env.local` 中现有的 `LLM_*` 设置。销售助手将对话文本发送给所配置的模型供应方，模型不可用时界面显示目录检索状态。询盘选型默认使用本地规则。

## Docker 工作台

```sh
docker compose up -d --build --wait
```

容器版工作台在 [localhost:8080](http://localhost:8080)。API 容器直接连接同一 PostgreSQL 服务。容器与本地开发入口共享账号、询盘和目录，数据卷为 `guanying-catalog_catalog_pg`。Compose 挂载工作簿目录用于双向同步，原始资料包以只读方式挂载。整库备份用 `pg_dump -Fc`，原始图片和 Excel 需要另行备份。

### 迁移已有获客数据

其他机器升级前先停止旧服务写入，准备一致的旧库副本（包含未合并的 WAL）。启动数据库，并在首次启动新版 API 前运行以下命令。选择主库作为第一个参数；可额外传入同一套演示数据的容器副本。导入会拒绝有不同业务数据的副本或已使用的目标库。迁移按原 ID 复制全部 17 张旧表，逐行比对后提交，并在 `backups/` 保存两份来源的压缩逻辑备份。一个来源时只备份该库。

```powershell
docker compose up -d --wait db
uv run --locked python -m scripts.migrate_leads data/leads.sqlite3
```

在「海外销售工作台」横栏下切换统计标签。默认打开「客户经营统计」，按已入档企业统计全部客户、北京时间今日新增、已确认成交、待分配和跟进中客户。点击数字或图表可查看对应企业，再打开档案。客户分布可切换国家 / 地区、业务类型和采购能力；分级沿用展会拓客的 A/B/C 与待评级，来源按首次入档统计。入档趋势可查看近 7 天、近 30 天或互不重叠的档龄区间。升级前缺少入档时间的企业列为“入档时间未知”。销售在「客户档案 → 编辑档案 → 成交记录」确认或撤回成交。

跟进中客户按关联了“跟进中”或“等客户补充”询盘的企业去重；待分配按档案负责人统计。「询盘跟进统计」展示待回、夜班、认领、询盘渠道分布及优先跟进队列，并展示展会线索、待核实记录、已核实关联企业和邀约草稿数。草稿按已保存的活动草稿计数。

「客户经营统计」中的「潜在客户推荐」卡片自动展示有来源的商用车候选。每行保留业务方向、等级和来源，点击条目在弹窗中查看推荐依据、待核实事项和原文链接。真实采购记录同步后会进入推荐筛选。开启网页搜索时，打开总览每天最多自动更新一次网页推荐，首个目标市场为马来西亚。

## 管理员与团队登录

未配置自动初始化时，从项目目录在交互式终端创建第一位管理员。命令会提示输入至少 12 个字符的临时密码。直接运行 Python 服务时，在使用相同 PostgreSQL 连接配置的终端执行第二种命令。

```sh
# Docker Compose
docker compose exec api python -m src.backend.api.accounts init-admin --username admin --name 工作台管理员

# 本地 Python
python -m src.backend.api.accounts init-admin --username admin --name 工作台管理员
```

打开工作台，用刚创建的账号登录并设置个人密码。点击侧栏底部的姓名，进入「成员管理」添加销售或管理员、停用账号或重置临时密码。成员可以在「我的账号」修改自己的密码和退出登录。忘记密码由管理员重置，管理员丢失密码时，部署维护者可运行 `docker compose exec api python -m src.backend.api.accounts recover-admin --username admin`。

希望空数据库启动时使用固定管理员凭据，可先运行 `docker compose exec api python -m src.backend.api.accounts hash-password` 并输入预定密码，再把生成的哈希值用单引号包裹，填入部署端 `.env` 的 `ADMIN_BOOTSTRAP_PASSWORD_HASH`。直接运行 Python 时传入同名环境变量。启动时若用户表为空，工作台会创建可直接登录的 `admin`。已有账号时，部署维护者可给 `recover-admin --username admin` 加上 `--permanent`，输入同一个密码后即可直接登录。

普通登录会话最长 8 小时，勾选「保持登录 14 天」后可跨浏览器重启保留会话。修改密码会使本账号其他设备退出，重置密码或停用会使该账号全部会话失效。HTTPS 部署设置 `SESSION_COOKIE_SECURE=1` 后重建 API 容器。项目的本地 HTTP 回环部署使用默认值 0。

## 三分钟走通销售流程

1. **买家发现**　选择“马来西亚／维修厂／已核验样例”，打开证据并将一家企业加入档案。配置搜索密钥后，切换“实时网页搜索”，可按地区分组选择国家或地区，也可选“自定义市场”输入城市等检索范围。查询失败和零结果会直接显示。
2. **客户档案**　核对企业官网、社交主页、公开业务联系方式、实际业务类型与采购能力，记录“统一备货还是客户自带”等下一步。来源页、已知业务事实和采购结论分别保留。
3. **渠道模拟器**　填入询价样例并发送；保持事件编号再次发送可验证去重。点击“同会话新消息”后修改原文，会追加到原单。可以改变接收时间来演示最近夜班。
4. **询盘收件箱**　进入新询盘，查看原文、来源、型号和原始数量单位，分配负责人并关联企业。登记线下实际发出的回复后，“未回复”标记消失。客户再次来信后恢复待回。无法自动接入的视频号原生评论可由销售补录。
5. **跨班交接**　“夜间待回”显示最近北京时间 20:00 至次日 08:00 期间还有未回复来信的有效询盘。“我的”“待认领”“已结束”支持不同岗位。跨渠道确认同一采购后，由销售选择目标询盘并合并。原消息、事件 ID 和跟进历史均保留。

## 展会拓客与邀约草稿

在侧栏进入「展会拓客」，也可从「买家发现」或具体客户档案进入。检索上海法兰克福或广交会时可指定届次、市场和关键词。默认检索带出处的公开资料和团队已登记的记录。上海展收录部分 2025 年优选买家代表，广交会收录第 138 届汽配供采对接会的公开报道。企业自行交换的名片或供采对接记录可整理为 UTF-8 CSV，表头含「企业名称」「来源链接」，可选「市场」「来源说明」。导入后在「核实记录」复查。

社媒原帖支持手动录入、实时网页搜索和免密的 Bluesky 原帖搜索。点击「查看原文」，核对发布方、买卖方向、日期和客户原句。输入摘录后可辅助判断意图，已配置模型时可能将摘录提交至该服务。已知发布人但企业归属不明的原帖可独立保存。网页搜索和采购联系页搜索使用同一服务端搜索配置。Bluesky 的市场输入作为检索词，其命中不证明注册地。

每条已核实证据可以关联客户档案。A级表示有商用车制动片或衬片的明确采购品类依据，B级表示相邻经营品类，C级表示仅核实企业或参会身份。买家取当前有效证据中的最高等级，撤回或改判后重新计算；采购能力沿用档案里的销售结论。买家名单可按等级、名称、业务角色和市场筛选并导出 Excel，工作簿含买家分级、核实依据及采购联系渠道。可整理采购邮箱、人员或部门、公司电话、WhatsApp、Facebook、微信、地址和供应商入口，每项均记录出处。

在买家详情填写英文展会名、起止日期、展馆与展位，可为已有业务邮箱或待确认收件人生成英文邮件草稿，保存修改或复制正文。相同企业、展会、日期和展位重用已有草稿。此流程没有邮件发送或推送操作。

## 国内社交渠道

在「买家发现」切换到「抖音和小红书」，输入关键词并点击「搜索线索」，由本机 MediaCrawler 发起新一轮采集。页面显示各平台进度及本次结果，平台要求登录时在运行采集的电脑上扫码。已导入的作品和评论可核实建档，企业自有作品的评论经确认后可转入询盘收件箱。详细步骤见[国内渠道联调](docs/MediaCrawler国内渠道联调.md)。

## 跟进受阻时寻找替代买家

在「询盘收件箱」选择询盘，关联企业档案后展开「寻找替代买家」。用已有的 L&R Haulage 档案和「本地公开资料」即可试用。未分派的询盘点击「认领并查找」，已有负责人的询盘点击「查找并推荐」。查找会保留原处理状态。

每次最多推荐三家。负责人可在侧栏「跟进简报 → 替代买家」中查看待办，其他成员仍可在共享询盘查看结果。交接询盘后，待办跟随当前负责人。已有客户显示档案与跟进负责人，新候选可加入客户档案。同一原企业的候选标记「不相关」后，再次查找会排除该候选。

本地模式使用带出处的公开企业资料，包括马来西亚车队、维修和配件经销企业，以及工作台内有核查日期和业务证据的档案。配置 Exa 或 Brave 搜索密钥后可主动选择实时搜索。推荐卡列出市场与业务重叠、业务原文、查阅日期、公开联系渠道和采购能力。只有负责人填写双方竞争事实和公开原文并确认后，才会显示「竞争关系已人工核实」。配置实时搜索时，编辑依据内也可主动检索同时提及双方的竞争线索。

「寻找替代买家」的实时查询遇到暂时性网络或服务错误时最多重试一次。服务不可用或搜索结果筛选后为空时，工作台会查找同市场同业务的本地公开资料。没有合适的本地资料时，可继续查看该询盘上一次的推荐。页面提示本次回退原因并标注当前结果来源。

买家发现、展会拓客和竞争线索共用有限重试。同一检索失败时，当前页面可继续显示上次成功结果。工作台总览在实时搜索失败或新结果全部被筛掉时，保留上一批可用的网页推荐及其更新时间。

## 可用数据及运行模式

| 能力 | 无密钥启动 | 接入条件 |
|---|---|---|
| 企业发现 | 三家已公开核验的马来西亚样例，按类型及关键词筛选 | `EXA_API_KEY` 或 `BRAVE_API_KEY` 开启实时搜索。搜索结果是待核验候选，企业经营地需核实 |
| 消息分析 | 本地中英等语言关键词和型号、数量规则，保留原文，可人工纠正意图 | 可选兼容 Chat Completions 的模型。显式设置 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY` 后，消息正文将发给指定供应方；接口失败回退本地规则 |
| 入站渠道 | 各渠道模拟、人工补录、持久化去重与人工回复登记 | 实时接收需要企业账号授权、平台订阅和公网 HTTPS 回调。渠道模拟器显示各平台最近接收结果 |
| 负责人 | 按当前登录成员筛选“我的”，负责人可从启用成员中分派 | `AUTO_ASSIGN=1` 给新询盘分配当前未结束工单最少的销售 |
| 演示与真实数据 | 首次初始化四条标记“模拟数据”的询盘及一条公开企业档案 | 干净部署前设置 `DEMO_DATA=0`。设置 `ENABLE_SIMULATOR=0` 可关闭模拟入口。已有数据不受参数切换影响 |

工作台和业务 API 使用团队账号及服务端会话。渠道回调沿用平台签名校验。正式对客报价以企业有效价目为依据。

使用 Compose 部署时，在项目 `.env` 中填写 `KOOYING_EXA_API_KEY` 或 `BRAVE_API_KEY`，执行 `docker compose up -d` 使配置生效。项目 Exa 密钥优先于通用的 `EXA_API_KEY`。直接运行 Python 时使用 `EXA_API_KEY` 或 `BRAVE_API_KEY` 环境变量。两种搜索服务都配置时优先使用 Exa。

### 社交渠道配置

在部署端的 `.env` 中按需填写以下变量，再执行 `docker compose up -d`。以 `_IDS` 结尾的变量支持同一应用下多个账号，用英文逗号分隔。渠道管理员在平台侧完成订阅后，使用另一个账号发送一条新询价进行联调。

| 渠道 | 服务端配置 | 收件范围 |
|---|---|---|
| WhatsApp | `WA_PHONE_NUMBER_IDS`、`WA_APP_SECRET`、`WA_VERIFY_TOKEN` | 指定商业号码收到的消息 |
| Instagram | `IG_ACCOUNT_IDS`、`IG_APP_SECRET`、`IG_VERIFY_TOKEN` | 指定专业账号收到的私信 |
| X | `X_USER_IDS`、`X_CLIENT_SECRET` | 公开提及、帖子回复、传统私信原文、加密聊天到达提醒 |
| TikTok | `TIKTOK_BUSINESS_IDS`、`TIKTOK_APP_SECRET` | 已获 Business Messaging 授权账号的完整入站私信事件 |
| Telegram | `TELEGRAM_BOT_ID`、`TELEGRAM_WEBHOOK_SECRET` | 客户与机器人的一对一消息 |
| LINE | `LINE_BOT_USER_ID`、`LINE_CHANNEL_SECRET` | 客户与官方账号的一对一消息 |

上述六个平台目前仅通过本地协议测试。真实账号的权限、订阅和投递仍需企业验证。销售在原渠道发送回复后，回工作台登记。[回调地址与分平台联调步骤](docs/接口与渠道联调.md#社交媒体收件)

| 路径 | 用途 |
|---|---|
| `src/frontend/` | Vue 3 销售工作台、TypeScript 接口类型、Vite 构建和 Nginx 配置 |
| `src/backend/` | `api/` 提供 FastAPI 入口、销售数据、发现与收件，`app/` 提供产品目录、选型和报价草稿 |
| `docs/` | 原始需求分析、获客调研和联调手册 |
| `tests/` | API 回归、并发去重、平台回调及真实浏览器烟测 |
| `scripts/` | 可重复执行的目标验收命令 |
| `compose.yaml` | 前后端镜像、健康检查、回环端口和持久化卷 |

## 验收

```sh
docker compose up -d --wait db
uv sync --locked
uv run python -m playwright install chromium
uv run python -m scripts.goal
```

仓库的 `goal` 验收入口从锁文件安装前端依赖，再执行 TypeScript 检查、Vite 构建、API 测试、Chromium 烟测和 Compose 配置检查。要同时构建并启动容器，可执行 `uv run python -m scripts.goal --docker`。该选项保留启动成功的服务供演示。
