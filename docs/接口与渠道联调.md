# 接口与渠道联调

## 销售与开发接口

交互式接口文档位于 `/docs`。下列路径由应用直接实现，异常以 HTTP 状态码及 `detail` 返回。

| 请求 | 用途 |
|---|---|
| GET /api/health、GET /api/config | 数据库健康、可用模式、销售选项和接收状态 |
| POST /api/discovery/search | market、kind、keywords 及 mode。mode 为 samples 或 live；缺密钥返回 503，服务失败返回 502 |
| GET /api/companies、POST /api/companies | 列出、保存企业，重复添加保留已核实信息 |
| PUT /api/companies/{id} | 修改企业身份、采购能力、公开联系方式、证据与备注 |
| POST /api/demo/inquiries、POST /api/inquiries/manual | 写入模拟或人工补录的渠道消息 |
| GET /api/inquiries、GET /api/inquiries/{id} | 队列摘要、完整消息和处理历史 |
| PATCH /api/inquiries/{id} | 分派负责人、纠正意图、选择客户档案、更新状态与下一步 |
| POST /api/inquiries/{id}/notes、…/reply | 留内部备注，或登记已经在原渠道发出的人工回复 |
| POST /api/inquiries/{id}/merge | 将本单并入请求中的 target_id，同时迁移会话路由 |
| GET/POST /webhooks/meta、GET/POST /webhooks/wechat | 平台挑战验证和真实事件接收 |

## 会话与团队账号

健康检查与平台回调可以独立调用。销售接口需要已完成首次改密的登录会话。浏览器和联调客户端对 `/api/` 的写请求均添加 `X-Workspace-Request: 1`。以 JSON 向 `POST /api/auth/login` 提交 `username`、`password` 和可选布尔值 `remember`，保留响应的 Cookie 供后续同源请求使用。临时密码登录后，先调用改密端点。

| 路径 | 用途 |
|---|---|
| GET /api/auth/me | 当前账号、角色、首次改密标志和会话截止时间 |
| POST /api/auth/password | 以 current_password 和 password 修改个人密码，同时轮换会话 |
| POST /api/auth/logout | 撤销当前会话，清除 Cookie |
| GET/POST /api/auth/members | 管理员列出成员或用 username、display_name、role、password 开通成员 |
| PATCH /api/auth/members/{id} | 管理员用 active 启停其他成员 |
| POST /api/auth/members/{id}/password | 管理员为其他成员设置临时密码并撤销已有会话 |

未登录或过期返回 401，权限不足或需要首次改密返回 403，重复账号或姓名返回 409，短时尝试过多返回 429。旧客户端传入的 actor 字段仅用于请求格式兼容，服务器从会话读取实际经办人。

## 替代买家接口

所有路径沿用销售会话和写请求头。询盘详情中的 `alternatives` 为当前关联企业的最近批次，首次查询前为 null。批次含检索条件、来源模式、时间及最多三张推荐卡。实时失败返回 502 或 503，成功且没有符合条件的企业返回空数组。

| 请求 | 行为 |
|---|---|
| POST /api/inquiries/{id}/alternatives | 提交 `source_company_id`、`mode`（local 或 live）与可选 `claim`。未分派时须明确认领。关联关系在检索过程中变化返回 409 |
| GET /api/alternatives/mine | 当前登录用户负责的待处理推荐 |
| POST /api/inquiries/{id}/alternatives/{rid}/feedback | 负责人提交 `decision`（adopted 或 dismissed）。入档操作由后端使用已保存的候选资料执行 |
| POST /api/inquiries/{id}/alternatives/{rid}/sources | 负责人主动查询同时提及双方的公开竞争线索，需要实时搜索配置 |
| POST、DELETE /api/inquiries/{id}/alternatives/{rid}/proof | 负责人提交公开 HTTP(S) 地址 `url` 和事实说明 `note`，或撤回先前的人工判断 |

## 模拟事件

发送 `POST /api/demo/inquiries`，Content-Type 为 application/json。将示例时间替换为想回放的时刻：

```json
{
  "channel": "messenger",
  "account": "export-team",
  "event_id": "fb-demo-001",
  "thread_key": "workshop-demo-A",
  "sender": "Workshop A (Demo)",
  "body": "Can you quote 100 sets of WVA 29289 for our workshop?",
  "occurred_at": "2026-11-21T02:30:00+08:00"
}
```

响应示例为 `{"inquiry_id":5,"duplicate":false}`，ID 以实际数据库为准。原样重发，duplicate 变为 true。仅更换 event_id 并追加客户消息，原询盘的消息数递增。新一轮独立询价可用新的 thread_key。来源可选 facebook_comment、messenger、facebook_form、wechat_kf、wechat_comment、manual。微信视频号原生评论支持模拟或人工录入。时间带时区后统一存 UTC。

## 平台回调

**Meta**　配置 META_APP_SECRET、META_VERIFY_TOKEN、META_PAGE_ID，在企业管理的 Page 上订阅应用。验证和事件地址均为公开 HTTPS 的 `/webhooks/meta`。feed 处理新增评论，messages 处理买家来信并跳过回声；leadgen 按线索 ID 读取表单字段，同时需要 META_GRAPH_VERSION（企业应用已获准使用的版本，如 vXX.X）与 META_PAGE_TOKEN。按 Meta 文档核对 pages_manage_metadata、pages_show_list、pages_messaging、leads_retrieval 及实际业务所需的其他权限。应用通过 HMAC 核验原始请求体。非本企业 Page 的事件被忽略。表单或平台读取失败返回非 2xx 并在渠道状态显示，可重放已签名的合法事件或人工补录。当前不提供主动拉取全部历史邮件、定时回补全部 Meta 留资或出站消息发送功能。[Page 回调](https://developers.facebook.com/docs/graph-api/webhooks/getting-started/webhooks-for-pages/) · [线索读取](https://developers.facebook.com/docs/marketing-api/guides/lead-ads/retrieving/)

**微信客服**　由企业管理员确认账号具备视频号场景的微信客服入口，配置 WX_CORP_ID、WX_KF_SECRET、WX_TOKEN 和 43 字符 WX_AES_KEY。接收地址为公开 HTTPS 的 `/webhooks/wechat`。接入验证解密 echostr，消息回调校验签名、解密和接收企业 ID，收到 kf_msg_or_event 后按客服账号串行调用 sync_msg；成功写入一页后保存游标。失败重试时依赖事件唯一键保护。超出平台读取窗口的消息可能需人工补录。该入口只处理客户进入微信客服后发出的咨询，原生私信和其他账号评论需单独核实接入条件。[微信客服接入](https://cloud.tencent.com/document/product/269/117050) · [接收消息与事件](https://developer.work.weixin.qq.com/document/path/94670)

**联调确认**　先用测试 Page 发送一条评论或私信、用获授权的测试表单提交一次；微信由测试客户向配置的客服账号发送一段带型号的文字。工作台应显示真实渠道来源、原文、唯一 ID、正确的负责人和最近成功接收时间。两次接收同一事件时应只有一条消息。平台回调的本地签名测试无法证明企业已完成安装与授权。对已有客服托管先核对冲突，避免更改生产接待配置。

## 部署信息

前端 Nginx 转发请求至 Compose 内部 api:8000。使用企业入口代理时，将外部回调限定在 `/webhooks/`，内网或企业认证保护其他路径。所有密钥只在服务端读取。备份 SQLite 时请通过 SQLite 在线备份接口或在停止写入后备份命名卷，避免只复制运行中的主文件而遗漏 WAL。销售交接时应填写实际发送的内容，手工登记不会向买家发送消息。
