# 接口与渠道联调

抖音和小红书的 MediaCrawler 检索、导出同步、自有作品评论转入询盘见[国内渠道测试手册](MediaCrawler国内渠道联调.md)。

## 销售与开发接口

交互式接口文档位于 `/docs`。下列路径由应用直接实现，异常以 HTTP 状态码及 `detail` 返回。

| 请求 | 用途 |
|---|---|
| GET /api/health、GET /api/config | 数据库健康、可用模式、销售选项和接收状态 |
| POST /api/discovery/search | market、kind、keywords 及 mode。mode 为 samples 或 live。缺密钥返回 503，搜索服务失败返回 502 |
| GET /api/companies、POST /api/companies | 列出、保存企业，重复添加保留已核实信息 |
| PUT /api/companies/{id} | 修改企业身份、采购能力、公开联系方式、证据与备注 |
| POST /api/demo/inquiries、POST /api/inquiries/manual | 写入模拟或人工补录的渠道消息 |
| GET /api/inquiries、GET /api/inquiries/{id} | 队列摘要、完整消息和处理历史 |
| PATCH /api/inquiries/{id} | 分派负责人、纠正意图、选择客户档案、更新状态与下一步 |
| POST /api/inquiries/{id}/notes、…/reply | 留内部备注，或登记已经在原渠道发出的人工回复 |
| POST /api/inquiries/{id}/merge | 将本单并入请求中的 target_id，同时迁移会话路由 |
| GET/POST /webhooks/meta、GET/POST /webhooks/wechat | 平台挑战验证和真实事件接收 |
| POST /webhooks/{平台} | 其他社交平台发送入站事件。WhatsApp、Instagram 和 X 在同一路径使用 GET 验证订阅 |

Compose 部署在项目 `.env` 中填写 `KOOYING_EXA_API_KEY` 或 `BRAVE_API_KEY`。直接运行 API 时读取 `EXA_API_KEY` 或 `BRAVE_API_KEY`。两家均已配置时使用 Exa。

## 会话与团队账号

健康检查与平台回调可以独立调用。销售接口需要已完成首次改密的登录会话。浏览器和联调客户端对 `/api/` 的写请求均添加 `X-Workspace-Request: 1`。以 JSON 向 `POST /api/auth/login` 提交 `username`、`password` 和可选布尔值 `remember`，保留响应的 Cookie 供后续同源请求使用。临时密码登录后，先调用改密端点。

| 路径 | 用途 |
|---|---|
| GET /api/auth/me | 当前账号、角色、首次改密标志和会话截止时间 |
| POST /api/auth/password | 以 current_password 和 password 修改个人密码，同时轮换会话 |
| POST /api/auth/logout | 撤销当前会话，清除 Cookie |
| GET/POST /api/auth/members | 管理员列出成员或用 username、display_name、role、password 开通成员 |
| PATCH /api/auth/members/{id} | 管理员用 active 启停其他成员 |
| POST /api/auth/members/{id}/password | 管理员为其他成员设置临时密码并撤销已有会话 |

未登录或过期返回 401，权限不足或需要首次改密返回 403，重复账号或姓名返回 409，短时尝试过多返回 429。旧客户端传入的 actor 字段仅用于请求格式兼容，服务器从会话读取实际经办人。

如需在空数据库启动时创建可直接登录的 `admin`，可在服务端配置 `ADMIN_BOOTSTRAP_PASSWORD_HASH`。已有账号的密码需通过改密或管理员恢复命令更新。 [管理员配置](../README.md#管理员与团队登录)

## 替代买家接口

所有路径沿用销售会话和写请求头。询盘详情中的 `alternatives` 为当前关联企业的最近批次，首次查询前为 null。批次含检索条件、实际来源模式、时间及最多三张推荐卡。实时检索命中为空或失败时依次尝试本地公开资料和上次可用的推荐。实时成功且无候选可回退时返回空数组。实时失败且无候选可回退时返回 502，未配置实时搜索返回 503。

实时检索的 POST 响应另含 `live_search`，其中 `sources` 是返回的网页来源数，服务失败时为 null。`fallback` 为 `local` 表示本地资料，为 `previous` 表示沿用上次推荐，无回退时为 null。

| 请求 | 行为 |
|---|---|
| POST /api/inquiries/{id}/alternatives | 提交 `source_company_id`、`mode`（local 或 live）与可选 `claim`。未分派时须明确认领。关联关系在检索过程中变化返回 409 |
| GET /api/alternatives/mine | 当前登录用户负责的待处理推荐 |
| POST /api/inquiries/{id}/alternatives/{rid}/feedback | 负责人提交 `decision`（adopted 或 dismissed）。入档操作由后端使用已保存的候选资料执行 |
| POST /api/inquiries/{id}/alternatives/{rid}/sources | 负责人主动查询同时提及双方的公开竞争线索，需要实时搜索配置 |
| POST、DELETE /api/inquiries/{id}/alternatives/{rid}/proof | 负责人提交公开 HTTP(S) 地址 `url` 和事实说明 `note`，或撤回先前的人工判断 |

## 模拟事件

发送 `POST /api/demo/inquiries`，Content-Type 为 application/json。将示例时间替换为想回放的时刻：

```json
{
  "channel": "messenger",
  "account": "export-team",
  "event_id": "fb-demo-001",
  "thread_key": "workshop-demo-A",
  "sender": "Workshop A (Demo)",
  "body": "Can you quote 100 sets of WVA 29289 for our workshop?",
  "occurred_at": "2026-11-21T02:30:00+08:00"
}
```

响应示例为 `{"inquiry_id":5,"duplicate":false}`，ID 以实际数据库为准。原样重发，duplicate 变为 true。仅更换 event_id 并追加客户消息，原询盘的消息数递增。新一轮独立询价可用新的 thread_key。来源可选 facebook_comment、messenger、facebook_form、wechat_kf、wechat_comment、whatsapp、instagram、x_dm、x_post、tiktok、telegram、line、manual。微信视频号原生评论支持模拟或人工录入。时间带时区后统一存 UTC。

## 平台回调

**Meta**　配置 META_APP_SECRET、META_VERIFY_TOKEN、META_PAGE_ID，在企业管理的 Page 上订阅应用。验证和事件地址均为公开 HTTPS 的 `/webhooks/meta`。feed 处理新增评论，messages 处理买家来信并跳过回声；leadgen 按线索 ID 读取表单字段，同时需要 META_GRAPH_VERSION（企业应用已获准使用的版本，如 vXX.X）与 META_PAGE_TOKEN。按 Meta 文档核对 pages_manage_metadata、pages_show_list、pages_messaging、leads_retrieval 及实际业务所需的其他权限。应用通过 HMAC 核验原始请求体。非本企业 Page 的事件被忽略。表单或平台读取失败返回非 2xx 并在渠道状态显示，可重放已签名的合法事件或人工补录。当前不提供主动拉取全部历史邮件、定时回补全部 Meta 留资或出站消息发送功能。[Page 回调](https://developers.facebook.com/docs/graph-api/webhooks/getting-started/webhooks-for-pages/) · [线索读取](https://developers.facebook.com/docs/marketing-api/guides/lead-ads/retrieving/)

**微信客服**　由企业管理员确认账号具备视频号场景的微信客服入口，配置 WX_CORP_ID、WX_KF_SECRET、WX_TOKEN 和 43 字符 WX_AES_KEY。接收地址为公开 HTTPS 的 `/webhooks/wechat`。接入验证解密 echostr，消息回调校验签名、解密和接收企业 ID，收到 kf_msg_or_event 后按客服账号串行调用 sync_msg；成功写入一页后保存游标。失败重试时依赖事件唯一键保护。超出平台读取窗口的消息可能需人工补录。该入口只处理客户进入微信客服后发出的咨询，原生私信和其他账号评论需单独核实接入条件。[微信客服接入](https://cloud.tencent.com/document/product/269/117050) · [接收消息与事件](https://developer.work.weixin.qq.com/document/path/94670)

**联调确认**　先用测试 Page 发送一条评论或私信、用获授权的测试表单提交一次；微信由测试客户向配置的客服账号发送一段带型号的文字。工作台应显示真实渠道来源、原文、唯一 ID、正确的负责人和最近成功接收时间。两次接收同一事件时应只有一条消息。平台回调的本地签名测试无法证明企业已完成安装与授权。对已有客服托管先核对冲突，避免更改生产接待配置。

## 社交媒体收件

将下列路径拼在本工作台公网 HTTPS 域名后作为回调地址。在服务器环境或 Compose 的 `.env` 填写对应值。每个平台独立启用；`_IDS` 使用企业授权的接收账号 ID，多个值用英文逗号分隔。平台管理员使用自己管理的应用完成授权和订阅。销售可在「渠道模拟器 → 渠道接入状态」查看配置及接收结果。

| 渠道与回调 | 设置与订阅 | 工作台收到什么 |
|---|---|---|
| WhatsApp · `/webhooks/whatsapp` | 在 Cloud API 注册业务号码，将 **Phone Number ID** 填入 `WA_PHONE_NUMBER_IDS`。用 Meta 应用密钥和自定验证令牌配置 `WA_APP_SECRET`、`WA_VERIFY_TOKEN`，订阅 WhatsApp Business Account 的 `messages` 字段并将应用订阅到目标 WABA。 | 文字、媒体说明、按钮等。送达和已读状态不建单。[消息回调](https://developers.facebook.com/documentation/business-messaging/whatsapp/webhooks/reference/messages) · [WABA 订阅](https://developers.facebook.com/docs/graph-api/reference/whats-app-business-account/subscribed_apps/) |
| Instagram · `/webhooks/instagram` | 在 Instagram Login 应用中授权专业账号并订阅 `messages`，按使用范围申请 `instagram_business_basic`、`instagram_business_manage_messages`。将专业账号 ID、该应用密钥、验证令牌填入 `IG_ACCOUNT_IDS`、`IG_APP_SECRET`、`IG_VERIFY_TOKEN`。 | 收件人为本账号的私信及附件类型。自己发送的消息和已读通知不建单。[Instagram Messaging](https://developers.facebook.com/documentation/business-messaging/instagram-messaging) · [回调字段](https://developers.facebook.com/docs/graph-api/webhooks/reference/instagram) |
| X · `/webhooks/x` | 配置企业用户 ID `X_USER_IDS` 与 OAuth 2.0 应用的 `X_CLIENT_SECRET`。用 X Webhooks API 注册地址并完成 CRC 验证，再通过 X Activity API 为目标 `user_id` 创建订阅并指定 `webhook_id`。可订阅 `dm.received`、`chat.received`、`post.mention.create`、`post.reply.create`。私有事件需账号本人授权。按控制台确认访问权限、费用及订阅有效期。 | 传统私信可读正文。XChat 只登记来信时间、会话与发送人，销售在 X 查看加密原文。公开帖子按会话与作者归并，同一条回复同时触发提及也只入库一次。[事件示例](https://docs.x.com/x-api/activity/event-payloads) · [订阅](https://docs.x.com/x-api/activity/introduction) · [回调验证](https://docs.x.com/x-api/webhooks/quickstart) |
| TikTok · `/webhooks/tiktok` | 申请 API for Business 的 Business Messaging 权限，完成数据安全和隐私审核并获企业账号授权。配置账号 `open_id` 到 `TIKTOK_BUSINESS_IDS`，配置开发者应用密钥 `TIKTOK_APP_SECRET`，通过 `/business/webhook/update/` 订阅 `DIRECT_MESSAGE`。 | `im_receive_msg` 包含买家、会话、消息编号和内容。仅含接收方和时间的 `im_receive_msg_eu` 无法定位买家，销售需到 TikTok 核对并补录。审核、地区及账号接收陌生私信的设置均会影响实际投递。[申请流程](https://business-api.tiktok.com/portal/docs/business-messaging-api-get-started/v1.3) · [企业消息事件](https://business-api.tiktok.com/portal/docs/subscribe-to-business-messaging-webhook-events-via-webhooks-api/v1.3) |
| Telegram · `/webhooks/telegram` | 创建销售机器人，用 `getMe` 确认数字 ID，填写 `TELEGRAM_BOT_ID`。为这个机器人生成独立随机串填入 `TELEGRAM_WEBHOOK_SECRET`。管理员用 Bot Token 调用 `setWebhook`，传入 HTTPS 地址、相同的 `secret_token` 和 `allowed_updates=["message"]`。每个机器人单独设置密钥。 | 客户发给机器人的一对一消息与常见附件。群、频道及机器人消息不进入队列。[Telegram Bot API](https://core.telegram.org/bots/api#setwebhook) |
| LINE · `/webhooks/line` | 为官方账号开通 Messaging API，在开发者控制台填回调地址，验证后启用 Use webhook。填写机器人的 user ID（回调的 `destination`）到 `LINE_BOT_USER_ID`，将 Channel secret 填入 `LINE_CHANNEL_SECRET`。 | 一对一消息与附件类型。平台的空验证批次、关注事件及群消息不建单。[接收事件](https://developers.line.biz/en/docs/messaging-api/receiving-messages/) · [验签](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/) |

### 联调验收

1. 用外部测试账号给目标企业账号发一条带产品编码和数量的询价。在工作台按渠道筛选，核对客户原文、发送时间、负责人和来源。对只有媒体的消息，在详情中核对附件类型。
2. 在原平台回复后登记人工回复，再让同一买家追加消息。原单应恢复待回。平台重试同一条来信时只保留一条。部署有多个授权账号时，用相同显示名分别向两个账号询价，应分成两单。
3. 「等待回调」表示已填服务端配置。本地模拟、错误签名、送达回执和空验证批次不会让新增渠道显示「已接收回调」。已验签且能归属到本账号的入站消息成功处理后，才记录成功时间。业务回调解析失败返回非 2xx，并在渠道状态中显示错误。

WhatsApp、Instagram、X、TikTok、Telegram 和 LINE 已用本地协议样例验证。企业账号安装、平台审核及实际投递仍待实号联调。工作台记录媒体类型或说明，附件原件在原平台查看。

## 展会拓客接口

以下接口位于 `/api/outreach`，继承工作台登录会话与写请求校验。

| 方法及子路径 | 用途 |
|---|---|
| GET 空路径，POST /search | 读取档案、证据、联系方式和草稿。搜索来源可选上海法兰克福、广交会、社媒原帖或企业采购资料，模式为 local、live 或仅用于原帖的 bluesky |
| POST /evidence，POST /import | 登记待核来源或将单届展会的 UTF-8 CSV 原子导入。按来源键去重，重复提交不覆盖核实结果 |
| POST /assess，PUT /evidence/{id} | 专门判断用户提交的摘录。核实记录提交上次读取的 updated 作为 version，并记录本次会话成员 |
| GET /buyers/{id}/contact-sources，POST /buyers/{id}/contacts，DELETE /buyers/{id}/contacts/{contact_id} | 查公开联系候选或在 live=true 时检索采购联系页，维护有来源和归属的联系方式 |
| GET /export.xlsx | 可带 grade 和 q，按照当前名单生成 Excel。没有留存证据的既有档案显示待评级 |
| POST /buyers/{id}/draft，PUT /drafts/{id} | 生成或读取同一展位活动的草稿，可编辑收件邮箱、主题和正文。并发编辑返回 409 |

搜索和模型调用在数据库写事务之外。数据库启动时为已有卷创建拓客表。Bluesky 原帖检索与企业账号收件订阅分别验收。真实展商账号、Facebook 私域内容和商业数据订阅由企业另行授权。

## 部署信息

前端 Nginx 转发请求至 Compose 内部 api:8000。使用企业入口代理时，将外部回调限定在 `/webhooks/`，内网或企业认证保护其他路径。所有密钥只在服务端读取。备份 SQLite 时请通过 SQLite 在线备份接口或在停止写入后备份命名卷，避免只复制运行中的主文件而遗漏 WAL。销售交接时应填写实际发送的内容，手工登记不会向买家发送消息。
