# 冠英销售选型工作台

## 启动

在项目根目录运行 `start-backend.bat`，再运行 `start-frontend.bat`。整合版使用 Docker Desktop、uv、Python 3.12、Node.js 22.12+ 和 npm。首次安装依赖需要联网。销售从询盘收件箱进入「智能选型」，独立目录维护界面可以在 5173 单开。账号初始化与启动命令见[项目说明](../README.md)。

| 服务 | 本地入口 | 启动行为 |
|---|---|---|
| 销售工作台 | http://127.0.0.1:5174 | 前端安装锁定依赖后执行 `npm run dev` |
| 统一 FastAPI | http://127.0.0.1:8081/docs | 同一进程处理获客、登录、目录选型、报价与 Excel 同步 |
| PostgreSQL 16 | 127.0.0.1:55432 | Compose 等待 db 健康，数据保存在项目独立命名卷中 |

两个开发服务分别在各自窗口用 Ctrl+C 停止。数据库可在项目根目录用 `docker compose stop db` 停止，命名卷保留下次使用。

## 国内刹车片目录

《国内刹车片目录.xlsx》按《冠隆产品册》原序收录鼓式 607 条、盘式 47 条。两张表均按唯一标识符、系列、名称、外弧、宽度、厚度、孔数、图片、适配车型排列。DCG 和 DCP 分别为国内鼓片和盘片，各从 0001 编号。表内图片来自对应的原行或规格卡。国内规格字段在此工作簿或 PostgreSQL 的 `domestic_catalog.parts` 中维护，后台同步两侧修改；保留行序和既有编号。

均厚写为两端相同的值，如 13/13。每个备选厚度单独占一行。江淮格尔后B 的括注 (18,20) 经确认拆为 18/18 和 20/20，与 10/18.5 分别编号。盘片原册所列长、宽可在工作台查看原始尺寸；外弧、厚度和孔数没有标注时留空。

## 外贸刹车片国别目录

英文册鼓片、盘片的维护入口为《外贸刹车片国别目录.xlsx》。第一列是规格唯一编号，第二列是冠英编号。按 PDF 行序分别建立欧洲、美国、日本、中国、韩国和无国别六张工作表，同名数据分区位于 PostgreSQL 的 `foreign_catalog` schema。旧工作簿仍提供国内目录、来源档案及历史数据；外贸制动片的技术字段以国别表为准。

外贸编号由 F、车辆国别字母、产品类型字母和四位流水组成。E/A/J/C/K/N 分别表示欧洲、美国、日本、中国、韩国及无国别，G/P 分别表示鼓片和盘片。每个前缀独立计数。中国表先收录第 10 页 CHINESE vehicle，再从第 12 页右侧东风系列顺延，含后段所有系列和第 30 页 52 款盘片。第 10～12 页 EXISTING MODELS 共 49 条，归入“无国别”表（FNG0001 至 FNG0049）。筛选任一车辆国别时，其候选范围同时包含 N 组；筛选其他车辆国别也包含 N 组。车型、尺寸及采购市场仍须核对。超过单个规格的系列卡片逐行编号，先读左印刷页，再读右印刷页，同一印刷页按卡片自上而下、同排先左后右排列。

尺寸只取当前来源册的表格单元格。图纸只供核对外形，遇到冲突或表格空白，均不取图上数字补录。盘片的“长度”单列，宽度和厚度分别进入 C、D；鼓片按原册 A/B/C/D 展开。无单位的弧形图标、卡片的 Taper、铆钉规格及铆钉直径（Rivet dia.）分别存储。WVA 等栏保留原栏中印出的文字，即使原文混有车型描述。对于“其他”系列，末列保留这个原册分组标题。

后台启动后会同步国别工作簿与六张表。维护现有规格时可修改单元格，保留首列、页内顺序和图列。PDF 页、行及图像位置由数据库的 `foreign_catalog.source` 保存，销售可用新编号查回原页。两端同时修改且内容不一致时，后台报告冲突。单独运行 `uv run python publish_foreign.py` 也可同步。重建带图 Excel 时，程序使用本机 Codex 的 Node 运行时，也可设置 `CATALOG_NODE_RUNTIME` 指向含 bin 和 node_modules 的运行时目录。

## 两册来源档案覆盖

英文产品目录 34 页整册归外贸，冠隆中文产品册 23 页整册归国内。英文册中的东风系列也归外贸。每条来源规格独立保存市场、尺寸、适配说明、原页和规格键。

| 数据口径 | 国内 | 外贸 | 待确认 | 合计 |
|---|---:|---:|---:|---:|
| 目录规格及展示项 | 657 | 991 | 0 | 1,648 |
| 独立照片组 | 0 | 0 | 133 | 133 |
| 工作台档案 | 657 | 991 | 133 | 1,781 |

目录同时包含配方系列、卷材、套装和修理包等展示项。原表一行明确列出多种厚度时，每种厚度独立登记。宣传与安装说明可在“逐页清单”定位。原来合并的 308 对规格已按来源拆开。销售维护某一市场的 SKU、价格和材质时，只更新选定的规格。

“图片索引”保留 524 条图片记录。133 个独立照片组缺少市场归属证据，暂列“待确认”。两册规格各自关联本册中的目录行或产品卡片，可直接查看原图。

“双册原始记录”逐条保留来源与规格。“双册对照”按鼓片名称或盘片参考号并列原文。371 组跨市场线索中，有 161 组的对比字段或规格集合存在差异。另有 207 组鼓片在所比尺寸与孔数上相符，3 组盘片前两维相符。各组均保留两侧独立规格，适配和可替换性需单独确认。例如 EQ1094 加宽的外贸外弧为 211，国内外弧为 206。

“待企业补充”随产品规格同步更新，按规格键列出缺项。本次导入后，1,405 条目录记录缺少已确认的冠英编号，国内鼓片有 211 条规格、国内盘片有 14 条规格缺少适配车型原文。国内 47 条盘片均缺少标称厚度。现有资料尚未提供可核验的逐规格材质、可售 SKU 和有效单价。可先用销量高的型号补齐材质、SKU、价格、币种、单位、价目依据及有效期，以便生成可计算的报价草稿。

源文件指纹、逐页 OCR、文字坐标、原行或卡片范围进入 PostgreSQL。销售可查看每条关联的原行、卡片和整页。转录使用离线 OCR、网格定位及局部原图复核。数据库中的非空外弧、宽度、厚度、孔数已逐条与来源观察比对；装车适配、SKU 和价格仍以企业核验为准。

## 唯一性与系列

- `catalog_product.code` 为厂内产品编号主键。每个已知冠英号只建一条产品记录。
- `catalog_spec.spec_id` 为稳定的规格唯一键。产品编号可为空；多个尺寸可通过同一冠英编号归到同一产品。不得把照片组、WVA 或供应商号当作冠英编号。
- 单规格目录记录可沿用冠英号作规格键。无编号规格和待核照片组使用独立键。后补冠英编号时保留既有规格键，否则会改变图片和历史单据的引用。
- Excel 新增规格可把规格唯一键留空，后台分配并回写。复制一行建立新尺寸时请清空复制来的规格键。
- 系列有来源时填写；未知系列保留空值。系列内按冠英编号自然排序，例如 2 排在 10 前，缺号记录按名称和标称厚度排序。名称相同只能提示复核。
- 销售端“产品目录”提供缺冠英编号、同号或同名多记录、照片组待核筛选。

## Excel 双向同步

若页面提示“全目录副本已同步，原工作簿待关闭”，当前编辑入口为《冠英产品知识库-全目录.xlsx》。关闭未修改的旧表后，后台自动回写原文件并切回原文件同步。如旧表也保存了新修改，系统会保留双方内容并提示合并。

编辑 `冠英产品知识库.xlsx` 的“产品规格”或“图片索引”，保留表头、列顺序和既有规格键。编号列按文本填写，保留前导零和后缀。供应商及料号按“供应商|完整料号”填写，例如“甲厂|A-007；乙厂|B-71”。同一编码栏支持分号或换行分隔多个号码。后台为每条映射生成可检索的记录，同一外部编号可命中多个规格。图片可用同一路径关联不同规格。价目有效期使用 YYYY-MM-DD。

后台每四秒检查一次。保存 Excel 后，后台整体校验并在一个 PostgreSQL 事务内更新。新增键、排序和数据库端改动会回写工作簿。Windows Excel 占用文件、需要回写时，请保存并关闭工作簿；后台自动重试。销售端约每八秒检查目录版本，更新后重新读取。模型不会修改目录。

删除 Excel 行会同步移除对应规格；删除有图片的规格时应同时调整图片索引。历史报价保留当时的快照。重复规格键、无效图片路径、悬空图片关联、非法价格或日期会阻止当次导入，已入库记录保持可用。状态显示在销售页右上角。

直接编辑数据库时，`catalog_spec.code` 必须引用已有的 `catalog_product.code`。新增产品及其规格请在同一事务提交。Excel 和数据库各自从上一次同步版本发生变化时，程序保留双方内容并报告冲突。可先备份工作簿，核对两侧记录，再将修改统一到相同内容后保存；未处理的冲突不会被自动覆盖。使用 Excel 作为日常维护入口可减少冲突。

## 销售操作

询盘接口 `POST /api/match` 先根据本轮对话和当前产品目录生成一级索引。返回的 `routing.slots` 分别记录采购市场、车辆国别、盘鼓类型及各自依据。销售指定的筛选条件优先，客户回答可修正前文。精确编码、目录型号及尺寸组合可以缩小分区。中英文只提供采购市场提示，送货地点与车辆国别分别判断。

`routing.status` 为 `resolved` 时才按分区读取二级产品详情。`needs_clarification`、`conflict` 和 `no_catalog` 分别表示需要补充信息、线索冲突和目录未覆盖，这三种状态返回追问且产品列表为空。确认某个外贸车系后也查该类型的 N 组。有完整产品编号时，`prefix` 表示该编号的真实前缀，`intent_prefix` 保留询盘条件对应的组。单一前缀仍可包含多条产品规格。

1. 在“对话选型”选择客户或销售，追加一条消息。模型提取默认开启，仅将当前询盘的对话发送到配置的服务；关闭开关可用本地规则查码。模型不可用时页面会标明回退模式。
2. 同型号横跨两册时，先确认采购国内版还是外贸版，在工作台选择市场，再核对候选尺寸、缺项、原页和细节图。照片组命中属于待核线索。单条命中表示当前目录中有相应记录。多产品采购建议拆成独立询盘。对话保存在当前网页会话，刷新会清空。
3. 选择一条规格，填写数量和单位，生成报价草稿。后端保存价格、币种、数量、材质、SKU 和价目依据的快照。价格、单位、材质、依据或有效期缺失时标记待核价。本版支持每个规格一条有效单价；未导入数量阶梯和真实价格。

可试查“WVA 19932”“BFMC SV/41/2”“EQ1094加宽”“富华桥12T”。第一组编码可定位 GYS-067。查询 EQ1094 加宽可以对照两册各自的原页、外弧和报价规格键。富华桥照片组仍需技术确认。

## 模型和配置

后端优先读取进程环境，其次读取配置文件。密钥保存在本机忽略的 `src/backend/.env.local`。切换兼容 Chat Completions 的服务时，修改 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL` 后重启后端。工作簿、前端构建和接口响应都不需要密钥。

后端分工为 `catalog.py` 管理字段和主键，`sync.py` 管理工作簿同步，`match.py` 提取条件与检索，`main.py` 提供销售 API 和草稿。前端技术为 Vue 3 和 Vite 8.3.4。根目录的 Compose 文件管理 PostgreSQL。

在 `src/backend` 运行 `uv run --locked python check_sync.py` 可复验双向同步、重复键回滚、同号多规格、自然排序和报价计算。测试使用临时 schema 和工作簿副本。
